# حسابرسی امنیتی (یافته‌های واقعی، نه فرضی)

## کلیدهای لورفته در فایل‌های ارسالی قبلی (استفاده نشدند، فقط گزارش)
- `bot.php`: ۳ کلید Fast-Creat API + جای خالی BOT_TOKEN/ADMIN_ID → اگر این‌ها را جایی استفاده کرده‌اید، **rotate کنید**.
- `telegram-ai-bot__1_.zip`, `telegram-ai-bot-github__1_.zip`, `modasr-arz-main`: هرکدام `.env` واقعی با BOT_TOKEN/GEMINI_API_KEY داشتند → قبلاً هم گفته شد: rotate کنید.
- `vak-sms.php`: کلید API وب‌سرویس + توکن ربات داخل کد.
- چند فایل در `PUBLIC.zip` (`SlowCreate/QwrnMinod.php`, `SlowFinder/*`, ...): توکن‌های تلگرام hardcode شده.
→ هیچ‌کدام این کلیدها در این مستندات یا کد تکرار نشدند.

## کد خطرناک شناسایی‌شده (استفاده نشد)
- `bot.php`: چند استفاده از `base64_decode` روی ورودی خارجی (بدون استفاده در پروژه‌ی ما).
- `PUBLIC.zip/beta ( mafia )/function.php`, `SlowFinder/index.php` و چند `index.html`: الگوی `eval(`/`base64_decode(` — بررسی عمیق نشد چون این فایل‌ها اصلاً استفاده نمی‌شوند.
- `PUBLIC.zip/SlowFinder/RQO/Location.php`: ارسال مخفیانه‌ی موقعیت جغرافیایی/IP قربانی به شخص ثالث بدون رضایت — **رد شد**، در پروژه استفاده نشد و نخواهد شد.

## این نسخه (کد تازه‌ساخته‌شده در همین پیام)
- کلید/توکن hardcode نشده؛ همه از `.env` (الگو در `.env.example`، placeholder خالی).
- پیام خطای کاربرِ Gemini هیچ‌وقت جزئیات فنی خام (پاسخ API، stack trace) را نشان نمی‌دهد؛ جزئیات فقط در لاگ سرور.
- تایم‌اوت و تعداد retry محدود برای همه‌ی فراخوانی‌های شبکه (Gemini، تلگرام، بله) — بدون حلقه‌ی بی‌نهایت.
- `.gitignore` شامل `.env`, `data/`, `*.db`.

## هنوز بررسی/ساخته نشده (ناقص بودنش را صریح اعلام می‌کنم)
- Rate limiting سمت سرور روی عملیات‌های گران (چت AI، دانلود) — در این هسته نیست؛ باید قبل از انتشار عمومی اضافه شود.
- وب/پنل ادمین و احراز هویتشان — هنوز وجود ندارد، پس چیزی برای حسابرسی هم نیست.
- بررسی امنیتی کامل تک‌تک ۸۰ سورس داخل `1_file_xvii.zip` انجام نشد؛ فقط بر اساس نام فایل‌ها فیلتر شدند. اگر لازم دارید یکی‌شان مرور دقیق شود، اسمش را بگویید.

## 🔴 یافته‌ی جدید: `.env`/`.env.bak` واقعی در آخرین آپلود (این دور)
فایل tar.gz که برای ادامه‌ی توسعه آپلود شد، شامل `.env` و `.env.bak` با مقادیر واقعی
(غیرخالی) برای `OPENROUTER_API_KEY`، `BOT_TOKEN`، `BALE_BOT_TOKEN`، `RUBIKA_BOT_TOKEN` بود.
- این مقادیر هیچ‌جا (کد، مستندات، خروجی ترمینال) در این دور چاپ یا تکرار نشدند؛ فقط طول
  رشته‌ها برای تایید «خالی نبودن» چک شد.
- `git log --all --full-history -- .env .env.bak` روی خود مخزن خالی برگشت → این دو فایل
  هیچ‌وقت کامیت نشده‌اند، پس به GitHub درز نکرده‌اند.
- **توصیه:** چون این مقادیر از طریق آپلود فایل در یک گفتگوی چت منتقل شدند (نه یک کانال
  کاملاً بسته‌ی بین شما و سرورتان)، به‌عنوان یک احتیاط استاندارد rotate کردن‌شان (برای
  OpenRouter، تلگرام و بله) منطقی است، حتی اگر این خاص این چت جایی درز نکرده باشد.
- در آینده پیشنهاد می‌شود هنگام ارسال نسخه‌ای از پروژه برای بررسی، `.env` را از tar/zip
  کنار بگذارید (یا با `tar --exclude='.env*'` بسازید).

## وضعیت پنل وب (این دور اضافه شد)
- رمز مدیر با PBKDF2 (۲۶۰٬۰۰۰ تکرار، salt تصادفی ۱۶ بایتی) هش می‌شود؛ رمز خام هیچ‌جا
  ذخیره یا لاگ نمی‌شود (`scripts/set_admin_password.py` با `getpass`، بدون echo).
- نشست‌ها فقط در حافظه‌ی پردازه‌اند (نه JWT، نه فایل)؛ با ری‌استارت سرور باطل می‌شوند.
  برای یک پنل تک‌ادمین قابل‌قبول؛ برای چند ادمین/چند پردازه باید به دیتابیس منتقل شود
  (در `auth.py` مستند شده).
- کوکی نشست `HttpOnly` است (جلوی خواندن با جاوااسکریپت را می‌گیرد) ولی `Secure` ندارد
  چون این سرور خودش TLS ندارد — **باید پشت reverse proxy با HTTPS باشد**، وگرنه کوکی
  نشست می‌تواند روی شبکه‌ی غیر-HTTPS شنود شود. این الزام در README و DEPLOYMENT تاکید شده.
- مقاومت brute-force فقط یک تاخیر ثابت ۰.۲ ثانیه‌ای روی لاگین است؛ rate limiting واقعی
  (مثلاً قفل موقت بعد از N تلاش ناموفق) هنوز اضافه نشده — برای یک پنل عمومی (نه پشت VPN
  یا IP-allowlist) باید قبل از انتشار عمومی اضافه شود.
- `/api/settings` مقدار کامل هیچ کلیدی را برنمی‌گرداند؛ فقط ۳ کاراکتر اول/۲ کاراکتر آخر
  (تست `test_settings_never_exposes_full_secret` این را تضمین می‌کند).

## وضعیت نصب VPS (این دور اضافه شد)
- سرویس‌ها با کاربر سیستمیِ غیرroot (`modasr`) اجرا می‌شوند؛ واحدهای systemd
  `ProtectSystem=strict`, `NoNewPrivileges=true`, `ReadWritePaths` محدود به `data/` دارند.
- `.env` بعد از نصب `chmod 600` می‌شود.
- اسکریپت `restore.sh` قبل از رونویسی `.env`/`data/` فعلی تایید دستی می‌خواهد (مگر `--yes`).
- **تست‌نشده روی VPS واقعی** — جزئیات در `docs/TEST_REPORT.md`.
